# ÒsánVault Africa — Enterprise Product Portfolio

## Portfolio principle

ÒsánVault should operate as a platform with independently packaged capabilities rather than a collection of unrelated applications.

### Foundation
- Identity and organization management
- Asset registry
- Document management
- Verification
- Audit and compliance controls
- Notifications
- Workflow
- API/SDK infrastructure

### Commercial modules
- ÒsánVault Assets
- ÒsánVault Verify
- ÒsánVault Invest
- ÒsánVault Treasury
- ÒsánVault Tokenization
- ÒsánVault Intelligence

Product names are provisional until branding is finalized. The architecture should use domain/service identifiers rather than hardcoded marketing names.

## Enterprise packaging

### Core Platform
Subscription/API access to the shared platform foundation.

### Professional modules
Specialized capabilities for asset owners, developers, investors, and institutions.

### Enterprise
Custom integrations, multi-tenant controls, dedicated environments, SLAs, reporting, and institutional workflows.

### Ecosystem
Country-specific and asset-class deployments built from the same platform contracts.

## Product design rule

Every module must expose:

- clear customer value
- defined data ownership
- API contract
- permission model
- audit requirements
- pricing/revenue hypothesis
- operational owner
- upgrade/deprecation path

No module should become a permanent dependency simply because it was the first implementation.
